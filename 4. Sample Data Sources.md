# **4. Sample Data Sources**

The performance of any deep learning model depends heavily on the quality and quantity of training data. In this lesson, we’ll explore suitable datasets for facial emotion recognition, how to acquire them, and—most importantly—how to structure them so that the training script can use them without modification. By the end, you’ll have a clear roadmap to obtain or create a dataset that matches the project’s expectations.

---

### 4.1 What the Project Needs

Looking back at `training/train.py`, the data is loaded via Keras’s `ImageDataGenerator.flow_from_directory`. This expects:

```
training/dataset/
├── train/
│   ├── angry/
│   ├── fear/
│   ├── happy/
│   ├── neutral/
│   ├── sad/
│   └── surprise/
└── val/
    ├── angry/
    ├── fear/
    ├── happy/
    ├── neutral/
    ├── sad/
    └── surprise/
```

Each subfolder contains grayscale (or colour—though the script converts to grayscale) images of 48×48 pixels (or any size; the script resizes them). The folder names **must** be exactly those class names (lowercase). If they differ, the alphabetical order of the folder names will dictate the class index mapping, and the `class_labels.json` file will be created accordingly.

Thus, any dataset that provides facial images with emotion labels can be adapted, provided we organise it in this folder‑based structure.

---

### 4.2 Primary Dataset: FER2013

The **FER2013** (Facial Expression Recognition 2013) dataset is the de facto standard for this task. It was introduced for the ICML 2013 Challenges in Representation Learning.

- **Number of images:** 35,887 grayscale images of size 48×48.
- **Classes:** 7 emotions: Angry, Disgust, Fear, Happy, Sad, Surprise, Neutral.
- **Format:** The dataset is usually distributed as a CSV file (`fer2013.csv`) where each row contains the pixel values (space‑separated integers, 48×48 = 2304 values) and an emotion label (0‑6).

For our project (6 classes), we discard the “Disgust” class (the least represented one, only ~547 images) because:
- The training script uses `num_classes=6`.
- Our `emotion_labels` list does not include “Disgust”.
- Removing it simplifies the problem without great loss, as “Disgust” is rare and hard to classify reliably.

**Mapping of CSV labels to our folder names:**

| Original label (FER2013) | Emotion | Our folder name |
|--------------------------|---------|-----------------|
| 0                        | Angry   | angry           |
| 1                        | Disgust | *ignored*       |
| 2                        | Fear    | fear            |
| 3                        | Happy   | happy           |
| 4                        | Sad     | sad             |
| 5                        | Surprise| surprise        |
| 6                        | Neutral | neutral         |

### 4.3 Obtaining FER2013 as Ready‑to‑Use Images

The Kaggle page [“FER2013” by ‘TONG’](https://www.kaggle.com/datasets/msambare/fer2013) provides the dataset already split into `train` and `test` folders, each containing subfolders for the 7 emotions. This is the **easiest starting point**.

**Steps:**
1. Go to Kaggle and download the dataset (you’ll need a Kaggle account).
2. Extract the archive. You’ll see:
   ```
   archive/
   ├── train/
   │   ├── angry/
   │   ├── disgust/
   │   ├── fear/
   │   ├── happy/
   │   ├── neutral/
   │   ├── sad/
   │   └── surprise/
   └── test/
       ├── angry/
       └── ... (same structure)
   ```
3. The `test` set will serve as our validation set. Rename `test` to `val` (or copy it) and remove the `disgust` folder from both `train` and `val` because we only have 6 classes.
4. Move the resulting `train` and `val` folders inside `training/dataset/`.

**Resulting path:** `training/dataset/train/` and `training/dataset/val/` with 6 subfolders each.

**Alternative: CSV conversion.** If you have `fer2013.csv`, you can convert it to the folder structure using a simple Python script:

```python
import pandas as pd
import cv2
import numpy as np
import os

# Read CSV
df = pd.read_csv('fer2013.csv')

# Mapping: original label -> folder name (0-angry,1-disgust,2-fear,3-happy,4-sad,5-surprise,6-neutral)
label_map = {0:'angry', 1:'disgust', 2:'fear', 3:'happy', 4:'sad', 5:'surprise', 6:'neutral'}
# We'll skip disgust (label 1)

base_dir = 'dataset'
split_dir = {'Training': 'train', 'PublicTest': 'val'}

for split in ['Training', 'PublicTest']:
    for idx, row in df[df['Usage'] == split].iterrows():
        label = row['emotion']
        if label == 1:  # skip disgust
            continue
        pixels = np.array(row['pixels'].split(), dtype='uint8')
        img = pixels.reshape(48, 48)
        folder = os.path.join(base_dir, split_dir[split], label_map[label])
        os.makedirs(folder, exist_ok=True)
        filename = os.path.join(folder, f'{idx}.jpg')
        cv2.imwrite(filename, img)
```

After running, delete the `disgust` folders if they exist.

### 4.4 Data Validation and Class Distribution

Once organised, check how many images each class has. FER2013 is imbalanced:

| Emotion  | Train (approx) | Val/Test (approx) |
|----------|----------------|-------------------|
| Angry    | 3,995          | 958               |
| Fear     | 4,097          | 1,024             |
| Happy    | 7,215          | 1,774             |
| Neutral  | 4,965          | 1,233             |
| Sad      | 4,830          | 1,247             |
| Surprise | 3,171          | 831               |

“Happy” has nearly twice as many samples as “Surprise”. This imbalance can bias the model. We can mitigate it with **class weights** (addressed later).

---

### 4.5 Alternative Datasets (When FER2013 Is Not Enough)

If you want to improve robustness or train a model for different conditions, consider these:

- **AffectNet:** ~450,000 images (manually annotated), 8 emotions (including contempt). Very large, requires more resources. Can be filtered to our 6 classes.
- **CK+ (Extended Cohn‑Kanade):** ~593 video sequences with posed expressions, very clean but small. You can extract frames and organise as before.
- **JAFFE:** 213 images of 10 Japanese female models, 7 emotions. Too small to train from scratch, but usable for fine‑tuning a pre‑trained model.
- **RAF‑DB:** Real‑world Affective Faces Database, ~30,000 images with compound expressions. Good for testing generalisation.

For the scope of this project, FER2013 is perfectly adequate. You can later augment it with additional data if needed.

### 4.6 Preprocessing Considerations Already Handled

The training script already applies:
- **Rescaling:** pixel values normalised to [0,1] by `rescale=1./255`.
- **Grayscale mode:** `color_mode='grayscale'` ensures the images are loaded as single‑channel (48×48×1).
- **Data augmentation:** random rotations, shifts, zooms, horizontal flip. This effectively increases the dataset size and forces the model to learn invariant features.

No additional manual preprocessing is required before feeding images to the generators.

### 4.7 Dealing with Class Imbalance (Optional Code Addition)

To handle class imbalance, we can pass `class_weight` to `model.fit`. Add this code block in `train.py` right before the `model.fit` call:

```python
from sklearn.utils import class_weight
import numpy as np

# Get class indices from generator
class_indices = train_generator.class_indices
class_weights = class_weight.compute_class_weight(
    'balanced',
    classes=np.unique(train_generator.classes),
    y=train_generator.classes
)
class_weight_dict = dict(enumerate(class_weights))
print("Class weights:", class_weight_dict)
```

Then modify the `model.fit`:
```python
history = model.fit(
    train_generator,
    validation_data=val_generator,
    epochs=epochs,
    callbacks=callbacks,
    class_weight=class_weight_dict,
    verbose=1
)
```

This makes the model pay more attention to underrepresented classes, improving minority‑class accuracy.

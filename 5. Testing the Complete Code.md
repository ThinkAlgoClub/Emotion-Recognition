# **5. Testing the Complete Code**

Now that every component is built and fixed, it’s time to verify that the whole system works together – from training to prediction. In this lesson you will learn how to test the backend, the frontend, and the full integration, plus how to debug common problems that arise during testing. No prior testing experience is assumed; we’ll go step by step.

---

### 5.1 Why Testing Is Important

- **Backend alone:** ensures the model loads, preprocessing works, and the `/predict` endpoint returns correct JSON.
- **Frontend alone:** confirms React renders correctly, buttons respond, and API calls are formed properly.
- **Integration:** the data must flow seamlessly from the user’s action (upload/capture) through the network to the model and back to the screen.
- **Edge cases:** we must test what happens when no file is sent, a non‑image file is uploaded, or the backend is down.

We’ll test each layer independently first, then the whole stack.

---

### 5.2 Testing the Training Script (if applicable)

If you have a dataset prepared, you can run the training script to generate the model and class labels.

**Steps:**
1. Open a terminal inside the `training/` directory.
2. Activate your virtual environment (if you haven’t already):
   ```bash
   # Windows: venv\Scripts\activate
   # macOS/Linux: source venv/bin/activate
   ```
3. Run:
   ```bash
   python train.py
   ```
4. **Expected output:**  
   - The generator prints the number of images per class, e.g., `Found 28709 images belonging to 6 classes.`  
   - Training begins showing epoch progress, loss, accuracy, val_loss, val_accuracy.  
   - Best model is saved to `../backend/model/emotion_model.h5`.  
   - File `../backend/model/class_labels.json` is created containing the class list.

**Checkpoints:**
- Look at the terminal output: if you see `ImportError: cannot import name 'BatchNormalization'`, your training script hasn’t been fixed.  
- If the generator finds fewer classes than expected, check your folder names – they must match exactly the lowercase emotion names (`angry`, `fear`, `happy`, `neutral`, `sad`, `surprise`).  
- If training stops because of missing directory `../backend/model/`, ensure you run the script from the `training/` folder; the relative path resolves from there.

**Test result:** After training finishes, you should have `emotion_model.h5` (a few MBs) and `class_labels.json` in `backend/model/`.

### 5.3 Testing the Backend in Isolation

We’ll test the Flask API without the frontend using **curl** or **Postman**.

#### 5.3.1 Start the Backend Server
In a terminal inside `backend/`:
```bash
# Activate venv if not active
python app.py
```
You should see:
```
 * Serving Flask app 'app'
 * Debug mode: on
 * Running on http://0.0.0.0:5000
```

If the server fails to start:
- **`FileNotFoundError: Model file not found`** → The `emotion_model.h5` is missing. Either train the model or place a pre‑trained model in `backend/model/`.
- **`ModuleNotFoundError: No module named 'flask'`** → Activate the correct virtual environment and run `pip install -r requirements.txt`.

#### 5.3.2 Health Check Endpoint
Open another terminal and run:
```bash
curl http://localhost:5000/health
```
Expected JSON response:
```json
{
  "status": "ok",
  "model_loaded": true,
  "labels": ["angry", "fear", "happy", "neutral", "sad", "surprise"]
}
```
The labels may vary if your class mapping is different, but they should be the six emotions.

#### 5.3.3 Test `/predict` with a Valid Image
You need a sample face image. For a quick test, you can download any clear frontal‑face picture from the web (e.g., a happy face selfie) and name it `test_happy.jpg`. Place it in `backend/` (or elsewhere).

Use curl to send the file:
```bash
curl -X POST http://localhost:5000/predict \
  -F "file=@test_happy.jpg" \
  -H "Content-Type: multipart/form-data"
```
Replace `test_happy.jpg` with the path to your image.

**Expected output** (example):
```json
{
  "confidence": 0.9872,
  "emotion": "happy",
  "probabilities": {
    "angry": 0.001,
    "fear": 0.002,
    "happy": 0.987,
    "neutral": 0.005,
    "sad": 0.003,
    "surprise": 0.002
  }
}
```
The exact numbers depend on the model, but the highest probability should match the dominant facial expression in your image. If not, the model may be poorly trained or the labels are misaligned.

#### 5.3.4 Test Error Cases
- **Missing file:**
  ```bash
  curl -X POST http://localhost:5000/predict
  ```
  → `{"error": "No file uploaded"}`, status 400.

- **Empty filename:**
  ```bash
  curl -X POST http://localhost:5000/predict -F "file=@"
  ```
  → `{"error": "Empty filename"}`, status 400.

- **Invalid file type (e.g., a .txt file):**
  ```bash
  echo "hello" > test.txt
  curl -X POST http://localhost:5000/predict -F "file=@test.txt"
  ```
  → `{"error": "Invalid file type. Allowed: png, jpg, jpeg, bmp, gif"}`, status 400.

- **Corrupted image:**  
  Create a file called `fake.jpg` that contains plain text:
  ```bash
  echo "not an image" > fake.jpg
  curl -X POST http://localhost:5000/predict -F "file=@fake.jpg"
  ```
  → Should return a 500 error with a message like `"cannot identify image file"`. This is expected because PIL cannot open it.

**Using Postman:**
- Create a new POST request to `http://localhost:5000/predict`.
- Under Body → form‑data, key = `file`, select an image file.
- Send. You’ll get the same JSON response.

### 5.4 Testing the Frontend in Isolation (Mocking the Backend)

You can test the React UI without a running backend by hardcoding a response.

**Temporary modification for UI test:**
In `App.js`, replace the `predict` function with:
```js
const predict = async () => {
  setLoading(true);
  setTimeout(() => {
    setResult({
      emotion: 'happy',
      confidence: 0.95,
      probabilities: { angry:0.01, fear:0.01, happy:0.95, neutral:0.01, sad:0.01, surprise:0.01 }
    });
    setLoading(false);
  }, 1000);
};
```
This simulates a successful API call.

**Test UI behavior:**
- Start the React app:
  ```bash
  cd frontend
  npm start
  ```
- Visit `http://localhost:3000`.
- **Upload mode:** Click “Upload Image”, choose a photo, see the preview. Click “Predict Emotion” → spinner appears, then result box with “happy” and 95%.
- **Webcam mode:** Switch to “Use Webcam”, allow camera, see your live feed. Click “Capture Photo”, see the captured snapshot. Click “Predict Emotion” → same simulated result.
- **Error simulation:** Change the `setTimeout` callback to `setResult({ error: 'Prediction failed' })` and verify the red error message.

Once confirmed, revert the `predict` function to the real axios call.

### 5.5 End‑to‑End Integration Test

This is the final test: real frontend ←→ real backend with a real model.

**Steps:**
1. **Start the backend** (Terminal 1):
   ```bash
   cd backend
   python app.py
   ```
2. **Start the frontend** (Terminal 2):
   ```bash
   cd frontend
   npm start
   ```
3. **Open the browser** at `http://localhost:3000`.
4. **Upload a face image:** Use a known happy face. Click “Predict Emotion”.
5. **Observe:** The loading spinner should appear, then the result should show the predicted emotion and confidence. Check the “All Probabilities” table – does the predicted emotion have the highest probability?
6. **Webcam test:** Switch to “Use Webcam”, capture a photo of your own face making a clear expression (e.g., a big smile). Predict. It should ideally predict “happy”. (Note: model accuracy may vary, especially with different lighting/angles. It’s okay if it’s not perfect – the test is that the pipeline works.)
7. **Test error recovery:** Stop the backend. Refresh the frontend, try to predict → you should see the error message “Network error…” or the backend’s error. Restart the backend; the app should work again without reloading.

### 5.6 Common Issues and Debugging Guide

| Symptom | Possible Cause | Solution |
|---------|----------------|----------|
| Frontend shows “Network Error” when backend is running | CORS not properly set, or wrong URL | Verify `flask-cors` is installed and `CORS(app)` is called. Check that the API base URL matches the backend address (`http://localhost:5000`). |
| Backend crashes with `Layer count mismatch` when loading model | Model trained with different TensorFlow/Keras version | Retrain the model with the same environment. If not possible, convert the model using `tf.keras.models.load_model(...)` with `compile=False` and recompile manually. |
| Prediction always returns the same emotion | Class labels not aligned between training and backend | Inspect `class_labels.json`; verify its order matches the model’s output indices. If the model was trained with a different order, retrain or rename folders. |
| Webcam shows black screen or no permission | Browser blocks camera, or no camera device | Check browser settings → allow camera for localhost. Ensure no other app uses the camera. Try incognito window. |
| `react-webcam` fails to load | Incorrect installation or version mismatch | `npm install react-webcam` again. Use version 5 or later (the component uses `getScreenshot`). |
| Memory warning in console about Canvas | Object URLs not revoked, but we fixed that. If you still see it, ensure you use the corrected `App.js`. |
| Backend returns 400 “Invalid file type” for a valid image | File extension missing or not allowed | Check that the file has `.jpg`, `.png`, etc. If the file is valid but extension is uppercase, modify the check in `app.py` to lower-case the extension. |
| Huge RAM usage or slow prediction | Model too large for hardware | Use the simple CNN (it’s tiny). If using transfer learning, reduce model size. |

### 5.7 Testing with Known‑Label Images (Validation)

For a more rigorous test, you can use a few images from the FER2013 validation set that you didn’t use during training. For example, take an image from `val/happy/` and rename it to `known_happy.jpg`. Send it to the backend via curl. The top predicted emotion should be “happy”. If it’s not, the model’s accuracy might be low (you can improve by training longer or tuning hyperparameters) or the label mapping is wrong.

This also demonstrates that the model hasn’t memorised the training data, because the validation image was not seen.

# **2. Deep Learning Backend – Code Explanation, Issues, and Fixes**

In this lesson, we’ll dissect the entire deep learning part of the project: the model training script and the Flask backend that serves predictions. We’ll look at every line, uncover potential bugs, missing pieces, and provide robust fixes. By the end, you’ll have a fully working backend, ready to handle real requests from the frontend.

---

### 2.1 What the Backend Does (Overview)

- **Training script (`training/train.py`):** Builds a Convolutional Neural Network (CNN) for emotion classification from 48×48 grayscale face images, trains it on a dataset organised in subfolders, and saves the best model as `emotion_model.h5`.
- **Flask app (`backend/app.py`):** Loads the trained model, exposes a `/predict` endpoint that accepts an image file, preprocesses it, runs inference, and returns the predicted emotion + confidence.
- **Utility (`backend/utils.py`):** Handles image preprocessing (grayscale conversion, resizing, normalisation, dimension expansion).

All these components must be perfectly aligned: input shape, class order, colour space, and normalisation.

### 2.2 Deep Dive: `training/train.py` – Building and Training the CNN

Let’s analyse the provided code line by line and note issues.

**Original code (abridged)**
```python

from tensorflow.keras.preprocessing.image import ImageDataGenerator
from tensorflow.keras.models import Sequential
from tensorflow.keras.layers import Conv2D, MaxPooling2D, Flatten, Dense, Dropout
from tensorflow.keras.callbacks import EarlyStopping, ModelCheckpoint, ReduceLROnPlateau
import os

train_dir = 'dataset/train'
val_dir = 'dataset/val'
model_save_path = '../backend/model/emotion_model.h5'
img_size = 48
batch_size = 64
num_classes = 6
epochs = 50

train_datagen = ImageDataGenerator(
    rescale=1./255,
    rotation_range=20,
    width_shift_range=0.2,
    height_shift_range=0.2,
    zoom_range=0.2,
    horizontal_flip=True

val_datagen = ImageDataGenerator(rescale=1./255)

train_generator = train_datagen.flow_from_directory(

val_generator = val_datagen.flow_from_directory(
    val_dir, target_size=(img_size, img_size), color_mode='grayscale',

model = Sequential([
    Conv2D(64, (3,3), activation='relu', input_shape=(img_size, img_size, 1)),
    BatchNormalization(),   # <--- ISSUE: Missing import!
    MaxPooling2D(2,2), Dropout(0.25),
    Conv2D(128, (3,3), activation='relu'), BatchNormalization(), MaxPooling2D(2,2), Dropout(0.25),
    Conv2D(256, (3,3), activation='relu'), BatchNormalization(), MaxPooling2D(2,2), Dropout(0.25),
    Flatten(), Dense(512, activation='relu'), Dropout(0.5),
    Dense(num_classes, activation='softmax')
])
...
```

#### Issues Found:
1. **Missing import:** `BatchNormalization` is used but never imported from `tensorflow.keras.layers`.
2. **Class label mismatch risk:** `flow_from_directory` sorts subfolder names alphabetically. If the folders are named `angry`, `fear`, `happy`, `neutral`, `sad`, `surprise` (typical FER2013 organisation), the class indices become:
   - 0: angry
   - 1: fear
   - 2: happy
   - 3: neutral
   - 4: sad
   - 5: surprise
   
   But the backend emotion list is `['Angry', 'Happy', 'Sad', 'Neutral', 'Surprise', 'Fear']`. This order **does not match** the alphabetical order, so predictions will be systematically wrong. For instance, index 0 would be mapped to “Angry” (correct) but index 1 “Happy” (wrong, it should be “Fear”). This is a critical bug.
3. **No saving of class indices:** The training script does not record the mapping from class index to emotion name anywhere. The backend later hard‑codes a list that might be wrong.
4. **Missing directory creation:** The line `os.makedirs(os.path.dirname(model_save_path), exist_ok=True)` is after `model.fit`, but it should be before `ModelCheckpoint` writes to that path, though `ModelCheckpoint` will create the directory if it doesn’t exist. Still, it’s safer to create it earlier.
5. **EarlyStopping patience:** 10 epochs is reasonable, but it might stop too early if validation loss fluctuates; adjust depending on dataset size.

### 2.3 Fixes for `train.py`

We’ll add the missing import, automatically build the emotion labels list from the generator, and save that mapping for the backend.

**Corrected `training/train.py`** (full code with fixes)

```python
# training/train.py
import tensorflow as tf
from tensorflow.keras.preprocessing.image import ImageDataGenerator
from tensorflow.keras.models import Sequential
from tensorflow.keras.layers import Conv2D, MaxPooling2D, Flatten, Dense, Dropout
from tensorflow.keras.layers import BatchNormalization          # FIX 1: added import
from tensorflow.keras.callbacks import EarlyStopping, ModelCheckpoint, ReduceLROnPlateau
import os
import json

# Paths
train_dir = 'dataset/train'
val_dir = 'dataset/val'
model_save_path = '../backend/model/emotion_model.h5'
labels_json_path = '../backend/model/class_labels.json'         # FIX 2: save mapping

# Parameters
img_size = 48
batch_size = 64
num_classes = 6
epochs = 50

# Data generators
train_datagen = ImageDataGenerator(
    rescale=1./255,
    rotation_range=20,
    width_shift_range=0.2,
    height_shift_range=0.2,
    zoom_range=0.2,
    horizontal_flip=True
)
val_datagen = ImageDataGenerator(rescale=1./255)

train_generator = train_datagen.flow_from_directory(
    train_dir,
    target_size=(img_size, img_size),
    color_mode='grayscale',
    batch_size=batch_size,
    class_mode='categorical'
)
val_generator = val_datagen.flow_from_directory(
    val_dir,
    target_size=(img_size, img_size),
    color_mode='grayscale',
    batch_size=batch_size,
    class_mode='categorical'
)

# Build class index mapping (dictionary: class_index -> emotion_name)
# train_generator.class_indices is like {'angry':0, 'fear':1, ...}
class_indices = train_generator.class_indices
# Invert it to get list ordered by index
idx_to_class = {v: k for k, v in class_indices.items()}
emotion_labels = [idx_to_class[i] for i in range(len(class_indices))]

# Save the labels for the backend
os.makedirs(os.path.dirname(labels_json_path), exist_ok=True)
with open(labels_json_path, 'w') as f:
    json.dump(emotion_labels, f)
print("Class labels saved:", emotion_labels)

# CNN model (same architecture, but now with BatchNormalization imported)
model = Sequential([
    Conv2D(64, (3,3), activation='relu', input_shape=(img_size, img_size, 1)),
    BatchNormalization(),
    MaxPooling2D(2,2),
    Dropout(0.25),

    Conv2D(128, (3,3), activation='relu'),
    BatchNormalization(),
    MaxPooling2D(2,2),
    Dropout(0.25),

    Conv2D(256, (3,3), activation='relu'),
    BatchNormalization(),
    MaxPooling2D(2,2),
    Dropout(0.25),

    Flatten(),
    Dense(512, activation='relu'),
    Dropout(0.5),
    Dense(num_classes, activation='softmax')
])

model.compile(optimizer='adam', loss='categorical_crossentropy', metrics=['accuracy'])

# Ensure model directory exists before training
os.makedirs(os.path.dirname(model_save_path), exist_ok=True)

# Callbacks
callbacks = [
    EarlyStopping(patience=10, restore_best_weights=True),
    ModelCheckpoint(model_save_path, save_best_only=True),
    ReduceLROnPlateau(factor=0.5, patience=5)
]

# Train
history = model.fit(
    train_generator,
    validation_data=val_generator,
    epochs=epochs,
    callbacks=callbacks,
    verbose=1
)

# Save final model (the best one is already saved, but this ensures we have the final epoch too)
model.save(model_save_path)
print(f"Model saved to {model_save_path}")
```

**Now the class order is guaranteed to match the training data.** The JSON file (`class_labels.json`) will look like `["angry", "fear", "happy", "neutral", "sad", "surprise"]` if the folders are named that way.

### 2.4 Deep Dive: Flask Backend – `app.py` and `utils.py`

#### `backend/utils.py`

```python
import numpy as np
from PIL import Image

def preprocess_image(image_file, target_size=(48,48)):
    img = Image.open(image_file).convert('L')   # Grayscale
    img = img.resize(target_size)
    img_array = np.array(img) / 255.0           # Normalise to [0,1]
    img_array = np.expand_dims(img_array, axis=-1)  # shape (48,48,1)
    img_array = np.expand_dims(img_array, axis=0)   # shape (1,48,48,1)
    return img_array
```

**Explanation:**
- `Image.open(image_file)` – image_file is a Werkzeug FileStorage object; PIL can read it directly.
- `.convert('L')` converts to grayscale (single channel), exactly what the model expects.
- Resize to 48×48.
- Normalise by dividing by 255 (training used `rescale=1./255`).
- Add channel dimension: `(48,48)` → `(48,48,1)`.
- Add batch dimension: → `(1,48,48,1)`.

**Potential issues:**
- If the user uploads a PNG with transparency, converting to 'L' discards alpha – fine.
- No error handling for corrupted images.

#### `backend/app.py`

Original code loads model and defines a `/predict` route.

**Issues:**
1. **Hard‑coded emotion_labels list** that likely does not match training classes.
2. **No check if model file exists** – app will crash at startup.
3. **Model loaded once at import time** – okay, but if the model file is large, this blocks startup; fine for small models.
4. **Lack of input validation** (only checks if file present, not file type).
5. **Prediction returns only top class** – not the full probability distribution. Could be enhanced.

### 2.5 Fixes for `backend/app.py`

We’ll load the class labels from the JSON file created during training. If the JSON doesn’t exist, we’ll fall back to a default (or raise an error). Also add a health‑check endpoint.

**Corrected `backend/app.py`**

```python
# backend/app.py
from flask import Flask, request, jsonify
from flask_cors import CORS
import tensorflow as tf
from utils import preprocess_image
import os
import json

app = Flask(__name__)
CORS(app)

# Load model with existence check
model_path = os.path.join('model', 'emotion_model.h5')
if not os.path.exists(model_path):
    raise FileNotFoundError(f"Model file not found at {model_path}. Train the model first.")

model = tf.keras.models.load_model(model_path)

# Load emotion labels dynamically
labels_path = os.path.join('model', 'class_labels.json')
if os.path.exists(labels_path):
    with open(labels_path, 'r') as f:
        emotion_labels = json.load(f)
    print("Loaded emotion labels:", emotion_labels)
else:
    # Fallback: default alphabetical order (matches common FER2013 folder naming)
    emotion_labels = ['angry', 'fear', 'happy', 'neutral', 'sad', 'surprise']
    print("Warning: Using default emotion labels. For correct results, ensure class_labels.json exists.")

@app.route('/predict', methods=['POST'])
def predict():
    if 'file' not in request.files:
        return jsonify({'error': 'No file uploaded'}), 400
    file = request.files['file']
    if file.filename == '':
        return jsonify({'error': 'Empty filename'}), 400

    # Optional: check file extension
    allowed_extensions = {'png', 'jpg', 'jpeg', 'bmp', 'gif'}
    if '.' not in file.filename or file.filename.rsplit('.', 1)[1].lower() not in allowed_extensions:
        return jsonify({'error': 'Invalid file type. Allowed: png, jpg, jpeg, bmp, gif'}), 400

    try:
        img_array = preprocess_image(file)
        predictions = model.predict(img_array)[0]   # shape (num_classes,)
        predicted_idx = int(predictions.argmax())
        emotion = emotion_labels[predicted_idx] if predicted_idx < len(emotion_labels) else "Unknown"
        confidence = float(predictions[predicted_idx])

        # Optional: return all probabilities
        all_probs = {emotion_labels[i]: float(predictions[i]) for i in range(len(emotion_labels))}

        return jsonify({
            'emotion': emotion,
            'confidence': confidence,
            'probabilities': all_probs
        })
    except Exception as e:
        return jsonify({'error': str(e)}), 500

@app.route('/health', methods=['GET'])
def health():
    return jsonify({'status': 'ok', 'model_loaded': True, 'labels': emotion_labels})

if __name__ == '__main__':
    app.run(host='0.0.0.0', port=5000, debug=True)
```

**Key improvements:**
- Model loading guarded with existence check.
- Emotion labels read from `class_labels.json` to guarantee alignment.
- Input file type validation.
- Returns full probability distribution for each emotion (useful for debugging).
- Added a `/health` endpoint to quickly verify backend status.

### 2.6 Additional Enhancements (Missing Code)

**Face Detection:** The current system assumes the uploaded image contains exactly one frontal face. In practice, users may upload a group photo or a picture without a face. For a production‑grade system, add face detection using OpenCV’s Haar cascade or a DNN face detector before cropping and passing to the emotion model.

*Example snippet for `utils.py`:*

```python
import cv2

def detect_face(image_array):
    face_cascade = cv2.CascadeClassifier(cv2.data.haarcascades + 'haarcascade_frontalface_default.xml')
    faces = face_cascade.detectMultiScale(image_array, scaleFactor=1.1, minNeighbors=5)
    if len(faces) == 0:
        return None
    # Assume the largest face
    x, y, w, h = max(faces, key=lambda rect: rect[2]*rect[3])
    return image_array[y:y+h, x:x+w]
```

Then in `preprocess_image`, you could call `detect_face` after converting to numpy array. If no face is found, return an error. We won’t force this into the core backend right now, but it’s a valuable “missing piece” that interviewers will ask about.

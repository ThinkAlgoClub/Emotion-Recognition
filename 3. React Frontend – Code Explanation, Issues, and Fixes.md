# **3. React Frontend – Code Explanation, Issues, and Fixes**

In this lesson, we’ll thoroughly examine the React frontend that lets users upload an image or take a webcam photo to predict emotions. I’ll walk you through every part of the code, point out what’s missing or broken, and provide corrected, production‑ready code. By the end, your `App.js` will be robust, user‑friendly, and ready to connect to the fixed backend.

---

### 3.1 High‑level Overview

The frontend is a single‑page React application with two modes:
- **Upload mode** – select an image file from disk, see a preview, and send it to the Flask backend.
- **Webcam mode** – stream from the camera, capture a frame, show a preview, and send it.

The prediction result (emotion name + confidence) is displayed after a successful response.

**Key dependencies:** `axios` (HTTP client), `react-webcam` (camera component).

---

### 3.2 Step‑by‑Step Code Explanation

Let’s go through the original `App.js` line by line, understanding each block.

```jsx
import React, { useState, useRef } from 'react';
import axios from 'axios';
import Webcam from 'react-webcam';
```

- `useState` for local state (mode, file, preview, result, loading).
- `useRef` to get a reference to the `Webcam` component so we can call `getScreenshot()`.

---

**State variables**
```jsx
const [mode, setMode] = useState('upload');   // 'upload' or 'webcam'
const [selectedFile, setSelectedFile] = useState(null);
const [preview, setPreview] = useState(null);
const [result, setResult] = useState(null);
const [loading, setLoading] = useState(false);
const webcamRef = useRef(null);
```
All straightforward. `preview` holds a blob URL (upload) or a data URL (webcam) to show the image.

---

**File upload handler**
```jsx
const onFileChange = (e) => {
  const file = e.target.files[0];
  setSelectedFile(file);
  setPreview(URL.createObjectURL(file));
  setResult(null);
};
```
When a file is selected, it creates a local object URL for the preview. **Issue:** the object URL is never released, which can cause memory leaks. A new URL is created every time the user picks a different file, and the old one is never revoked. Also, if the component unmounts, the URL stays in memory.

---

**Webcam capture**
```jsx
const capturePhoto = () => {
  const imageSrc = webcamRef.current.getScreenshot();
  fetch(imageSrc)
    .then(res => res.blob())
    .then(blob => {
      const file = new File([blob], "webcam.jpg", { type: "image/jpeg" });
      setSelectedFile(file);
      setPreview(imageSrc);
      setResult(null);
    });
};
```
`getScreenshot()` returns a base64 data URL. To convert it to a `File` object (required by `FormData`), the code fetches the data URL as a blob, then creates a `File`. This is functional but:
- It does not handle errors (fetch failure).
- The data URL itself is set as `preview`, which is fine.
- The `File` name is hardcoded “webcam.jpg”.

---

**Send prediction request**
```jsx
const predict = async () => {
  if (!selectedFile) return;
  setLoading(true);
  const formData = new FormData();
  formData.append('file', selectedFile);
  try {
    const response = await axios.post('http://localhost:5000/predict', formData);
    setResult(response.data);
  } catch (error) {
    console.error(error);
    setResult({ error: 'Prediction failed' });
  }
  setLoading(false);
};
```
- Builds a `FormData` object with the `selectedFile`.
- POSTs to the backend.
- On success, sets `result` to the JSON response.
- On failure, sets a generic error message; it does **not** extract the backend’s detailed error (e.g., `error.response.data.error`).

---

**UI rendering**
- Buttons switch between modes.
- Conditional rendering for upload / webcam.
- A `Predict Emotion` button that is disabled when no file is selected or while loading.
- The result block shows either an error or emotion + confidence + a progress bar.

Everything is styled with inline objects (`btn`, `activeBtn`, `predictBtn`).

---

### 3.3 Issues and Missing Pieces

1. **Memory leak – unreleased object URLs**  
   `URL.createObjectURL` creates a blob URL that must be released with `URL.revokeObjectURL`. Without cleanup, memory grows each time a file is selected.

2. **Poor error handling for network errors**  
   The catch block ignores the actual server error. If the backend returns a 400 with `{"error": "Invalid file type"}`, the user only sees “Prediction failed”.

3. **No feedback while loading**  
   The button text changes to “Predicting…”, but there is no spinner or visual cue. This is minor, but a loader improves UX.

4. **Webcam permission handling**  
   If the user denies camera access, the `Webcam` component will throw an error. The code does not catch this; the camera area just remains blank. Users should see a friendly message.

5. **Hard‑coded backend URL**  
   `http://localhost:5000` works during development, but if the backend is deployed elsewhere, the URL must be changed. It’s better to use an environment variable or a proxy.

6. **No cleanup on component unmount**  
   If the user navigates away while a preview URL exists, it should be revoked.

7. **Webcam preview dimensions**  
   The captured screenshot may have different aspect ratio than the webcam display, but that’s minor.

8. **Missing all‑probabilities display**  
   The backend now returns `probabilities` for all emotions. The frontend doesn’t show them, limiting the user’s insight. (Enhancement, not a fix.)

9. **No input validation on client side**  
   The file input accepts all image types, which is fine, but an additional size limit could be added (backend might reject large files).

---

### 3.4 Fixes and Improved Code

Let’s rewrite `App.js` with all these fixes. I’ll add a `useEffect` cleanup, better error extraction, a loading spinner, webcam error state, and configurable API base URL.

**Corrected `frontend/src/App.js`**

```jsx
import React, { useState, useRef, useEffect } from 'react';
import axios from 'axios';
import Webcam from 'react-webcam';

// Use an environment variable or fallback to localhost
const API_BASE = process.env.REACT_APP_API_URL || 'http://localhost:5000';

function App() {
  const [mode, setMode] = useState('upload'); // 'upload' or 'webcam'
  const [selectedFile, setSelectedFile] = useState(null);
  const [preview, setPreview] = useState(null);
  const [result, setResult] = useState(null);
  const [loading, setLoading] = useState(false);
  const [webcamError, setWebcamError] = useState(null);
  const webcamRef = useRef(null);
  const previewUrlRef = useRef(null); // to track the object URL

  // Clean up object URL whenever preview changes or component unmounts
  useEffect(() => {
    return () => {
      // Revoke the previous object URL if any
      if (previewUrlRef.current) {
        URL.revokeObjectURL(previewUrlRef.current);
        previewUrlRef.current = null;
      }
    };
  }, []);

  // Helper to set preview and handle old URL
  const setImagePreview = (url) => {
    // Revoke previous object URL only if it's a blob URL (not data URL)
    if (previewUrlRef.current && previewUrlRef.current.startsWith('blob:')) {
      URL.revokeObjectURL(previewUrlRef.current);
    }
    previewUrlRef.current = url;
    setPreview(url);
  };

  // Handle file upload
  const onFileChange = (e) => {
    const file = e.target.files[0];
    if (!file) return;
    setSelectedFile(file);
    const url = URL.createObjectURL(file);
    setImagePreview(url);
    setResult(null);
  };

  // Capture webcam photo
  const capturePhoto = () => {
    const imageSrc = webcamRef.current.getScreenshot();
    if (!imageSrc) return;

    // Convert data URL to File without fetch (faster)
    const byteString = atob(imageSrc.split(',')[1]);
    const mimeString = imageSrc.split(',')[0].split(':')[1].split(';')[0];
    const ab = new ArrayBuffer(byteString.length);
    const ia = new Uint8Array(ab);
    for (let i = 0; i < byteString.length; i++) {
      ia[i] = byteString.charCodeAt(i);
    }
    const blob = new Blob([ab], { type: mimeString });
    const file = new File([blob], 'webcam.jpg', { type: mimeString });

    setSelectedFile(file);
    setImagePreview(imageSrc); // data URL, no need to revoke
    setResult(null);
  };

  // Predict emotion
  const predict = async () => {
    if (!selectedFile) return;
    setLoading(true);
    const formData = new FormData();
    formData.append('file', selectedFile);

    try {
      const response = await axios.post(`${API_BASE}/predict`, formData, {
        headers: { 'Content-Type': 'multipart/form-data' },
      });
      setResult(response.data);
    } catch (error) {
      console.error(error);
      // Extract server error message if available
      const msg =
        error.response?.data?.error ||
        'Network error. Please check your connection and try again.';
      setResult({ error: msg });
    } finally {
      setLoading(false);
    }
  };

  // Handle webcam permission errors
  const handleWebcamError = (err) => {
    console.error('Webcam error:', err);
    setWebcamError('Could not access webcam. Please check permissions or use upload mode.');
  };

  return (
    <div style={{ textAlign: 'center', marginTop: '30px', fontFamily: 'Arial' }}>
      <h1>🎭 Emotion Recognition</h1>
      <div>
        <button
          onClick={() => { setMode('upload'); setWebcamError(null); }}
          style={mode === 'upload' ? activeBtn : btn}
        >
          Upload Image
        </button>
        <button
          onClick={() => { setMode('webcam'); setWebcamError(null); }}
          style={mode === 'webcam' ? activeBtn : btn}
        >
          Use Webcam
        </button>
      </div>

      {mode === 'upload' && (
        <div>
          <input type="file" accept="image/*" onChange={onFileChange} />
          {preview && <img src={preview} alt="preview" width="250" style={{ margin: '20px' }} />}
        </div>
      )}

      {mode === 'webcam' && (
        <div>
          {webcamError ? (
            <p style={{ color: 'red' }}>{webcamError}</p>
          ) : (
            <>
              <Webcam
                audio={false}
                ref={webcamRef}
                screenshotFormat="image/jpeg"
                width={350}
                mirrored
                onUserMediaError={handleWebcamError}
                style={{ margin: '20px', borderRadius: '10px' }}
              />
              <br />
              <button onClick={capturePhoto}>Capture Photo</button>
              {preview && (
                <div>
                  <h4>Captured:</h4>
                  <img src={preview} alt="captured" width="150" />
                </div>
              )}
            </>
          )}
        </div>
      )}

      <div style={{ margin: '20px' }}>
        <button
          onClick={predict}
          disabled={!selectedFile || loading}
          style={predictBtn}
        >
          {loading ? (
            <>
              <span className="spinner" /> Predicting...
            </>
          ) : (
            'Predict Emotion'
          )}
        </button>
      </div>

      {result && (
        <div
          style={{
            marginTop: '30px',
            padding: '20px',
            backgroundColor: '#f0f0f0',
            borderRadius: '10px',
            display: 'inline-block',
            maxWidth: '90%',
          }}
        >
          {result.error ? (
            <p style={{ color: 'red' }}>{result.error}</p>
          ) : (
            <>
              <h2>
                Detected Emotion:{' '}
                <span style={{ color: '#2c7da0' }}>{result.emotion}</span>
              </h2>
              <p>Confidence: {(result.confidence * 100).toFixed(2)}%</p>
              <progress value={result.confidence} max="1" style={{ width: '250px', height: '20px' }} />
              {/* Show all probabilities if available */}
              {result.probabilities && (
                <div style={{ marginTop: '15px', textAlign: 'left' }}>
                  <h4>All Probabilities</h4>
                  {Object.entries(result.probabilities).map(([emotion, prob]) => (
                    <div key={emotion} style={{ margin: '3px 0' }}>
                      <span style={{ display: 'inline-block', width: '80px' }}>{emotion}</span>
                      <progress value={prob} max="1" style={{ width: '150px', height: '12px' }} />
                      <span style={{ marginLeft: '8px' }}>{(prob * 100).toFixed(1)}%</span>
                    </div>
                  ))}
                </div>
              )}
            </>
          )}
        </div>
      )}
    </div>
  );
}

// Basic inline styles
const btn = {
  margin: '10px',
  padding: '8px 16px',
  cursor: 'pointer',
  backgroundColor: '#ddd',
  border: 'none',
  borderRadius: '5px',
};
const activeBtn = {
  ...btn,
  backgroundColor: '#2c7da0',
  color: 'white',
};
const predictBtn = {
  marginTop: '20px',
  padding: '10px 20px',
  fontSize: '16px',
  cursor: 'pointer',
  backgroundColor: '#61dafb',
  border: 'none',
  borderRadius: '5px',
};

// Add a simple CSS spinner (you can place this in index.css or as a style tag)
const styleSheet = document.createElement('style');
styleSheet.innerText = `
  .spinner {
    display: inline-block;
    width: 14px;
    height: 14px;
    border: 2px solid rgba(255,255,255,0.3);
    border-radius: 50%;
    border-top-color: #fff;
    animation: spin 0.8s linear infinite;
    margin-right: 6px;
  }
  @keyframes spin { to { transform: rotate(360deg); } }
`;
document.head.appendChild(styleSheet);

export default App;
```

### 3.5 Explanation of Fixes

1. **Memory leak fixed** – `useEffect` cleanup revokes the previous object URL when the component unmounts. `setImagePreview` revokes old blob URLs before setting a new one.
2. **Better error handling** – extracts `error.response.data.error` from the server if available; otherwise shows a generic network message.
3. **Loading spinner** – a CSS spinner is injected dynamically (or can be moved to `index.css`). The button shows a spinner + “Predicting…” while loading.
4. **Webcam error handling** – the `onUserMediaError` callback sets `webcamError`, and the UI shows a red message instead of a broken webcam.
5. **Configurable API URL** – uses `REACT_APP_API_URL` environment variable; falls back to localhost:5000. This also makes it easier to use a proxy if desired (e.g., adding `"proxy": "http://localhost:5000"` in `package.json` and using relative URL `/predict`).
6. **Data URL conversion improved** – the old `fetch` method is replaced with a synchronous base64‑to‑blob conversion, which is faster and has no risk of fetch errors.
7. **All probabilities display** – if the backend returns a `probabilities` object (as it does after our fix), we render a small table of all emotions with progress bars.
8. **Better button styling** – added `max` attribute to the `<progress>` element (React requires `max="1"` to work properly).

### 3.6 Additional Notes – Proxy Setup (Optional)

If you prefer to avoid hardcoding the backend URL, you can add a proxy in `frontend/package.json`:

```json
{
  ...
  "proxy": "http://localhost:5000"
}
```

Then in `App.js`, change the API call to:

```js
const response = await axios.post('/predict', formData);
```

React’s development server will forward any unknown requests to the Flask backend, and you won’t need the `API_BASE` variable. However, for production, you would still need to configure the actual backend URL.
